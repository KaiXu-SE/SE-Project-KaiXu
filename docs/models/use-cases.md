# KaiXu 用例图与关键场景

[用例图源文件](use-cases.drawio)可用 draw.io 打开，包含系统上下文、核心对象关系，以及个人工作区与规划、账号与小组协作、外部接入与扩展、非功能验收四页用例图。用例页的人类主参与者位于系统边界左侧，提供授权数据或提取结果的外部系统位于右侧。图上的用例编号对应 [SRS 用例规约](../requirements/srs.md#功能用例)和[需求追溯矩阵 v0](../requirements/traceability-matrix.md)。非功能页的验收人员是执行测试的角色。

## 手动创建任务

对应 [UC-02](../requirements/srs.md#uc-02-创建和维护任务)，M1。

- **前提** 用户打开 Windows 桌面端，可处于未登录的本地模式。
- **主流程** 用户键入或粘贴标题，按需填写截止日期和估时、选择工作区，确认后创建任务。课程任务可从全局列表和所属工作区打开。
- **异常分支** 标题为空时保留当前表单并提示补全。取消录入时正式任务数保持原值。
- **走查** 先键入标题并保存，确认只新增一项独立任务，截止日期和工作区为空。再把标题粘贴到标题栏，填写截止日期并选择课程工作区后保存，确认只新增一项课程任务。重启后核对两项任务的标题、截止日期和工作区。在所属工作区修改课程任务的标题，再从全局列表打开该任务，应看到同一条任务及更新后的标题。

## 完成任务并处理未来时段

对应 [UC-08](../requirements/srs.md#uc-08-提交任务完成与剩余估时)，M1 验个人任务，M2 验共享任务。

- **前提** 一个未完成任务已有一条本人历史时段和两条本人未来时段。
- **主流程** 用户选择完成，系统列出未来时段。用户选择保留或取消后确认，任务状态与时段处置一并保存。选择保留时两条未来时段仍在日程，选择取消时释放这两段时间，历史时段均保留。
- **异常分支** 关闭弹窗或保存失败时，任务状态和所有时段保持原值；保存失败时保留选择以供重试。共享任务的其他成员仍可查看自己的原时段。
- **走查** 分别执行保留、取消与关闭弹窗，核对任务详情、日／周视图及共享场景中的第二个账号。

## 拉取并确认 Canvas 作业

对应 [UC-04](../requirements/srs.md#uc-04-拉取并确认-canvas-作业)，M3。

- **前提** 用户已授权读取一门真实课程，课程内有一条可拉取的作业。
- **主流程** 用户只读拉取作业并核对候选。候选可查看标题、截止日期（如有）、原作业链接。确认后生成一条正式任务；再次拉取同一作业时按来源标识关联到该任务。界面显示上次成功拉取时间，并保存候选的已核对版本。
- **异常分支** 取消确认时正式任务数保持原值。来源截止日期变化时展示原值、本地值与新值，用户确认后才应用，保留本地负责人和私人时段。授权失效时提示重新授权，可继续使用已导入任务，也可手动录入。来源删除或撤回时只提示来源变化，本地任务及其状态保留。
- **走查** 记录确认前正式任务数为零，首次确认和重复拉取后为一。同账号两个客户端分别提交相同与不同内容，核对同一任务与待确认差异。再用截止日期变更和授权撤销验证提示，记录脱敏的验收证据。

## 预览并导入学期课表

对应 [UC-19](../requirements/srs.md#uc-19-预览并导入标准课表)，M3。

- **前提** 用户具备一份符合团队约定格式、包含若干课程及上课时间的课表文件。
- **主流程** 上传后预览解析出的课程匹配和对应上课时间。用户确认后，创建或匹配课程工作区，同时写入相应上课固定事件。重复导入时复用已匹配的记录。
- **异常分支** 格式错误时提示原因以便修正后重试。解析失败、用户取消或确认后的写入失败时，正式课程与事件均保持原值，写入失败保留预览供重试。
- **走查** 分别记录预览阶段、确认后和第二次导入后两类记录的数量，并在课程工作区及全局日程核对关联。另用含新增课程的课表模拟事件写入失败与重试，确认失败时无部分写入，重试成功后无重复。

## 并发编辑与离线补传

对应 [UC-11](../requirements/srs.md#uc-11-维护共享任务与共同事件)、[UC-13](../requirements/srs.md#uc-13-管理登录和桌面离线同步)和 [UC-22](../requirements/srs.md#uc-22-验证保存重试与版本一致性)，M2。

- **前提** A 与 B 是同一项目的有效成员，两人都能编辑同一共享任务。B 的 Windows 桌面端已登录。
- **主流程** B 在断网时修改任务并重启，读取原待同步修改。A 在线保存同一任务的新版本。B 重连后，系统显示两份修改，保留 B 的输入，经 B 核对后按当前版本重新提交。
- **异常分支** 响应丢失时重试同一保存操作只生效一次。重连若暂未取得权限结果，相关变更保持待同步。确认 B 已被移除后，清理受限共享缓存、草稿和待同步操作，本人时段与备注按撤权规则保留。
- **走查** 用两个账号分别核对重启恢复、版本冲突、同一请求重试和撤权后的读取与提交结果。

## 管理工作区与归档恢复

对应 [UC-01](../requirements/srs.md#uc-01-管理课程与项目工作区)、[UC-24](../requirements/srs.md#uc-24-查看工作区概览)，M1 验个人工作区，M2 验共享访问边界。

- **前提** 学生可在 Windows 访客模式创建工作区，归档共享项目需当前所有者。
- **主流程** 输入课程或项目名称和简介，项目按需关联一门课程。保存后从概览进入任务、近期日程或资料。归档时核对影响并确认，之后从历史列表查看或恢复。
- **异常分支** 名称为空、权限不足或取消时保持原数据。归档的工作区内容只读，已存在的本人时段仍可由本人调整。归档课程时关联项目保留自己的状态。
- **走查** 建立课程及一个关联项目，归档并恢复课程，核对原链接、原记录及已取消时段的状态。用无课程权限的项目成员核对私有课程提示和无权限响应。

## 新建、调整或取消本人时段

对应 [UC-06](../requirements/srs.md#uc-06-将任务安排到多个私人时段)和 [UC-07](../requirements/srs.md#uc-07-发现排期冲突与超期)，M1。

- **前提** 学生持有一个未完成、尚可排期的任务，日程中已有一个固定事件。
- **主流程** 查看任务截止日期及已有时段，填写两个不同日期的起止时间。校验本人重叠及超期，调整或明确确认后保存。任务详情与工作区、全局日程引用同一批时段。
- **异常分支** 结束不晚于开始时拒绝并保留输入。首尾相接按半开区间通过。任务缺截止日期或估时仍允许手动排期，保存前如有新冲突再提示。仅取消一个时段时保留任务和其余时段。
- **走查** 验证实际重叠、首尾相接以及工作时段排到用户时区截止日次日的情况。
  - 以 `Asia/Tokyo` 为用户时区，把未完成任务的截止日期设为 `2026-12-11`。分别在该时区的 `2026-12-11 23:59` 和 `2026-12-12 00:00` 查看任务，应依次显示未逾期和逾期，截止字段均显示 `2026-12-11`。
  - Android 日程可用后，用系统时区不同、用户时区相同的 Windows 和 Android 复测。加入来源时间为 `2026-12-11T20:30:00-05:00` 的日程测试数据，两个客户端在 `Asia/Tokyo` 均应显示 `2026-12-12 10:30`。

## 维护资料、任务关联和附件历史

对应 [UC-09](../requirements/srs.md#uc-09-维护工作区资料并关联任务)和 [UC-16](../requirements/srs.md#uc-16-管理附件版本与授权下载)，M1 验链接与文本，M3 验关联与附件。

- **前提** 学生或项目成员对工作区资料有写权限，上传附件时处于联网状态。
- **主流程** 录入资料名称及链接或文本，核对可见范围后保存。可按名称查找，在同一工作区的任务中关联并打开资料。附件升级记录上传者、时间与版本，版本完整后再切换当前文件。
- **异常分支** 无效链接保留名称与说明。中断传输时继续允许下载旧版本，恢复旧附件时生成新版本。删除资料前展示受影响的任务数，确认后解除引用并保留任务。
- **走查** 用两个任务关联同一资料，验证仅解除一个引用、删除资料和版本恢复的结果。再用撤权账号验证下载拒绝。

## 确认共享并邀请成员

对应 [UC-10](../requirements/srs.md#uc-10-邀请成员和撤回访问)和 [UC-18](../requirements/srs.md#uc-18-交接所有权并管理项目生命周期)，M2。

- **前提** 项目所有者已登录，受邀者具备项目账号。
- **主流程** 所有者先核对将公开的任务及其来源、共同事件和项目资料，确认后发出邀请。受邀者查阅项目和角色，确认加入后读取获准内容。
- **异常分支** 撤销、过期或被其他人使用的邀请不可建立新成员关系。同一成员仍有权限时，重复接受返回已有关系。退出或移除后重用旧邀请时拒绝加入。所有者提名现有成员交接时，由对方接受才生效。
- **走查** 用两个测试账号验证共享确认、重复接受、拒绝交接、成功交接，以及被移除后原会话的读写请求和使用旧邀请加入的请求均被拒绝，确认私人数据不在共享内容内。

## 维护共同事件

对应 [UC-11](../requirements/srs.md#uc-11-维护共享任务与共同事件)和 [UC-25](../requirements/srs.md#uc-25-查看和汇报共享进度)，M2。

- **前提** 项目未归档，两名成员都具有允许的读写权限。
- **主流程** 一名成员输入共同事件的名称和有效起止时间，根据系统提示处理本人的重叠后确认。服务端核对成员资格与版本后保存。另一名成员刷新可查看同一事件及修改者和时间。
- **异常分支** 项目视图只返回当前操作者本人的冲突信息。提交期间权限被收回或项目归档时拒绝保存。遇到版本冲突时保留修改供比较。
- **走查** 以相同版本并发修改，验证两份输入得到正确结果，再确认删除并验证第二个账号刷新后的状态及同一请求重试结果。

## 从共享任务安排自己的工作时段

对应 [UC-12](../requirements/srs.md#uc-12-保留并隔离私人安排)和 [UC-25](../requirements/srs.md#uc-25-查看和汇报共享进度)，M2。

- **前提** 任务可访问，两名成员分属各自账号且项目未归档。
- **主流程** 成员查看共同的负责人、截止时间和状态，把任务安排到自己的私人时段。在项目页报告共享进度，其他成员刷新只读取可共享信息。
- **异常分支** 任务改截止时提醒本人复核，系统保留原排期。共享任务被删除或本人失去权限时，将相关时段转为独立个人记录，保留起止与本人备注，释放共享关系与来源。
- **走查** 分别使用两个账号规划同一任务，核对界面与接口。撤权后再查原链接和重连结果，验证本人记录可查且共享详情无残留。

## 核对课程群消息提取

对应 [UC-03](../requirements/srs.md#uc-03-核对群消息提取候选)，M3 扩展。

- **前提** 学生选定授权范围内的一条通知，通知包含两项作业，其中一项日期含糊。
- **主流程** 用户检查接收方和将发送的内容，提取范围仅包含经核对的选定正文，系统保持候选与原文关联，显示两项建议并标注待核对字段。用户选定事项和类型，补字段后确认。
- **异常分支** 闲聊和嵌入在文本里的指令不得触发正式写入。重试仍按作业分别去重。取消后忽略迟到结果，保留手动录入入口。
- **走查** 比较确认前后和重复提取后的正式记录，记录各字段正确、待核对或人工修正的数量。

## 验证本地库升级和失败回退

对应 [UC-26](../requirements/srs.md#uc-26-验证本地库升级和回退)，适用于涉及 Windows 本地库结构变更的增量。

- **前提** 用含任务、时段和已交付资料关系的旧版测试库，记录各条数据及关联。
- **主流程** 升级前生成可读取的备份。在一份副本执行迁移并重启新版，核对原记录与关系。
- **异常分支** 在另一份测试副本中模拟迁移失败，恢复升级前备份并用原版打开。确认可继续工作且不会混用新旧数据结构。
- **走查** 留存旧版与新版构建、备份校验记录、两条路径的结果及重启前后数据比较。
