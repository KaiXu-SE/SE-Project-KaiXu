# 用户故事清单

说明：本清单为用户故事初稿，共整理 **14 条用户故事**（12 条功能需求 + 2 条非功能需求）。每条均附需求来源和 `Given / When / Then` 验收标准，后续将进一步补充至不少于 20 条用例，并逐条建立 GitHub Issue 分配负责人。

---

## 一、功能性用户故事（US-01 至 US-12）

### US-01：创建与管理课程及项目工作区
- **用户故事**：作为学生用户，我希望按课程和项目分别建立工作区，并允许把课程项目关联到对应课程，以便把同一门课的任务、日程和资料放在一起查看。
- **来源**：IV-01、IV-03；竞品分析第 3 节
- **验收标准**：
  - Given 用户在工作区列表页，When 选择“课程”或“项目”类型、填写名称并保存，Then 系统创建对应工作区并在目录中可见；项目可选择关联一门已有课程或保持独立。
  - Given 工作区名称为空，When 用户点击保存，Then 系统提示名称必填并保留其余已填输入，不创建空工作区。
  - Given 用户归档一个已结课的工作区，When 确认归档，Then 该工作区从默认列表隐藏，但历史任务、日程和资料仍可回查且支持恢复。

### US-02：手动创建任务与独立个人事项
- **用户故事**：作为学生用户，我希望快速创建任务，填写标题、可选的截止日期、预计时长、优先级以及所属工作区（或无归属），以便既能管课程作业也能记日常个人事务。
- **来源**：IV-02、IV-05
- **验收标准**：
  - Given 用户打开新建任务页面，When 仅填写标题并保存，Then 任务成功创建并允许截止日期、预计时长和工作区为空；无截止日期的任务不会被标记为逾期。
  - Given 用户将任务归属到某工作区，When 打开该工作区任务页和全局任务页，Then 两个视图显示的是同一条任务，在一处修改后另一处同步反映最新内容。

### US-03：获取课程群消息并借助 AI 辅助提取为任务或日程（扩展项）
- **交付分类**：扩展项
- **用户故事**：作为学生用户，我希望软件能按我指定的范围获取或导入课程群消息，并借助 AI 辅助识别其中的作业、考试或会议通知，生成待确认的任务或固定事件候选项，以便省去翻群抄写且不漏掉重要安排。
- **来源**：IV-02
- **验收标准**：
  - Given 用户在授权范围内选定课程群及消息范围（或导入选定聊天记录并自动识别内容），When 触发获取并执行自带密钥的 AI 辅助提取与输出校验，Then 系统生成待确认候选项列表（含建议类型“任务/固定事件”、标题、时间或截止日期、建议工作区及原文引用），用户确认前不写入正式任务或日程。
  - Given 群消息中包含无关闲聊、重复通知或时间表述模糊的内容，When 系统提取候选项，Then 无关闲聊不生成候选项，日期不明确的字段标为待核对而不编造具体时间，疑似重复事项给出提示。
  - Given 用户修改并确认候选项，When 点击保存，Then 系统创建正式任务或固定事件并保留来源原文；若用户取消、拒绝建议或 AI 不可用，不产生残留记录，且仍可手动录入。

### US-04：外部 Canvas 作业拉取与课表导入及去重确认
- **用户故事**：作为学生用户，我希望读取授权范围内的 Canvas 作业并导入标准格式学期课表，核对候选项无误后再批量入库（课表导入确认后同时建立课程工作区与对应上课固定事件）。
- **来源**：IV-02；竞品分析第 1 节
- **验收标准**：
  - Given 用户使用获授权账号触发一门真实 Canvas 课程的只读作业拉取，When 系统解析完成，Then 展示含标题、截止日期（如有）和原作业链接的候选列表，未确认前不写入正式工作区、任务或日程；若授权失效，则提示原因，保留已导入任务并支持继续手动录入。
  - Given 同一 Canvas 作业（或同一外部来源记录）被连续获取 2 次及以上，When 再次同步，Then 系统按来源唯一标识去重，不创建重复任务；若外部截止日期发生变化，则提示差异由用户逐项确认，且不覆盖本地负责人和个人排期。
  - Given 用户上传约定格式的学期课表文件，When 系统解析完成并经用户预览确认，Then 未确认前不写入正式数据；确认后同时建立对应的课程工作区与上课固定事件（固定时段），重复导入同一课表不产生重复工作区或重复固定事件。

### US-05：管理固定事件并查看全局/局部日程
- **用户故事**：作为学生用户，我希望录入上课、考试、会议等固定事件，并在日视图、周视图和工作区视图中同时看到固定事件与个人安排，以便一眼看清每天还剩哪些空闲时间。
- **来源**：IV-01
- **验收标准**：
  - Given 用户新建一条固定事件，When 填写有效标题与起止时间（结束晚于开始）并保存，Then 该事件同时出现在对应日期的全局日/周视图及所属工作区日程中。
  - Given 用户输入的结束时间早于或等于开始时间，When 点击保存，Then 系统拒绝保存，给出明确错误提示并保留已有输入。

### US-06：为任务安排多个个人工作时段（与截止日期分离）
- **用户故事**：作为学生用户，我希望为同一项大任务在不同的日子安排多个具体的个人工作时段，以便提前消化多门课的复习和项目工作量，而不是等到截止前才赶工。
- **来源**：IV-01、IV-05
- **验收标准**：
  - Given 存在一项未完成任务，When 用户为其新增两段不同日期的工作时段，Then 任务详情同时保留原截止日期与这两段执行时间，且日程视图按实际时段展示。
  - Given 用户删除其中一段工作时段，When 确认删除，Then 仅移除该时段，原任务及另一段工作时段保持不变。

### US-07：排期时间冲突与超出截止日期提示
- **用户故事**：作为学生用户，我希望在新增或调整工作时段和固定事件时，系统自动检查与我本人已有安排的重叠以及是否超过任务截止日期，以便及时调整计划、避免撞车。
- **来源**：IV-01
- **验收标准**：
  - Given 用户在周三 14:00–16:00 已有固定课程，When 为某任务安排周三 15:00–17:00 的工作时段，Then 系统按半开区间 `[开始, 结束)` 检出时间重叠，列出冲突对象，允许用户返回修改或明确确认保留。
  - Given 上一段安排在 14:00–15:00、下一段安排在 15:00–16:00，When 保存安排，Then 相邻首尾相接不被误判为冲突。
  - Given 任务截止日期为周五，When 用户把工作时段排到周六，Then 系统提示超出截止日期，允许修改或明确确认例外，且不改写任务原截止日期。

### US-08：完成任务与未完成剩余估时反馈
- **用户故事**：作为学生用户，我希望在标记任务完成时能选择取消或保留后续已预留的工作时段，在任务未完成时能更新剩余预计时长，以便日程始终反映真实的待办情况。
- **来源**：IV-05
- **验收标准**：
  - Given 某未完成任务有 1 条历史时段和 2 条未来工作时段，When 用户将该任务标为“已完成”并在提示弹窗中选择“取消未来时段”并确认，Then 任务状态更新为“已完成”，1 条历史时段完整保留，2 条未来工作时段均被取消并从日/周日程及任务未来排期中移除（对应时段释放为空闲）。
  - Given 某未完成任务有 1 条历史时段和 2 条未来工作时段，When 用户将该任务标为“已完成”并在提示弹窗中选择“保留未来时段”并确认，Then 任务状态更新为“已完成”，1 条历史时段完整保留，2 条未来工作时段继续保留在原日期与时间段中并在日程视图可见（关联任务状态同步显示为“已完成”）。
  - Given 系统在标记完成时已展示上述 2 条未来时段并弹出确认询问，When 用户撤销确认或关闭弹窗，Then 任务保持原未完成状态不变，1 条历史时段与 2 条未来工作时段均保持原样，不做任何改动。
  - Given 任务尚未完成，When 用户修改本人剩余预计时长并调整后续时段，Then 剩余时长更新且历史已过时段记录保持完整。

### US-09：在工作区维护学习资料并与任务关联
- **用户故事**：作为学生用户，我希望在课程或项目工作区里保存课件链接、简短备忘或文件附件，并把资料关联到具体作业任务上，以便开始写作业时直接打开所需资料，不再受微信群文件过期困扰。
- **来源**：IV-03
- **验收标准**：
  - Given 某课程工作区已有资料 A，When 用户在同工作区的任务详情中选择关联资料 A，Then 任务详情展示资料 A 入口，点击不超过 2 次即可打开链接、查看文本或下载附件。
  - Given 用户从任务中解除对资料 A 的关联，When 确认解除，Then 资料 A 仍保留在工作区资料列表中，不级联删除。
  - Given 用户删除工作区中的资料 A，When 点击删除，Then 系统先提示受影响的关联任务数量，确认后解除引用并保留这些任务。

### US-10：邀请成员加入项目并控制角色权限
- **用户故事**：作为项目所有者，我希望将项目升级为小组共享、生成邀请让组员加入，并在成员退出或被移除后立刻收回其访问权限，以便安全可控地开展小组课程项目。
- **来源**：IV-04
- **验收标准**：
  - Given 项目所有者首次将个人项目转为共享，When 发起共享操作，Then 系统列出将被公开的任务、事件与资料并要求所有者确认，同时明确不会公开私人工作时段。
  - Given 所有者生成有效邀请，When 受邀用户确认加入，Then 建立项目成员关系且重复接受不产生重复成员记录；超过有效期或被撤销的邀请无法加入。
  - Given 所有者移除成员 B 或成员 B 主动退出，When 成员 B 再次访问该项目页面或直接请求项目/文件接口，Then 服务端立即拒绝访问；项目历史记录保留。

### US-11：协同维护共享任务、共同事件与项目资料
- **用户故事**：作为项目成员，我希望在共享项目中新增或修改任务、指派负责人、记录状态与简短阻碍、维护共同会议事件以及更新共享资料，以便全组随时对齐进度而不用在群里反复追问。
- **来源**：IV-03、IV-04
- **验收标准**：
  - Given 成员 A 和成员 B 同属项目 P，When 成员 A 修改任务负责人、状态或阻碍说明并保存，Then 记录显示最后修改人与时间，成员 B 刷新后可见最新状态。
  - Given 成员 A 和成员 B 基于同一旧版本同时编辑同一共享任务，When 成员 A 先保存成功、成员 B 后提交，Then 系统检测版本冲突，拒绝静默覆盖，保留成员 B 的输入并展示服务端最新版本供其比较后重新提交。

### US-12：将共享任务排入个人私人时段并严格保密
- **用户故事**：作为项目成员，我希望把小组项目里的共享任务排进我自己的个人日程，同时确保我的具体工作时段和个人剩余估时对其他队友完全不可见，以便既能兼顾个人课表又不暴露隐私。
- **来源**：IV-04
- **验收标准**：
  - Given 成员 B 为项目 P 的共享任务创建了个人工作时段，When 项目所有者或成员 A 查看项目进度、任务详情或调用项目接口，Then 返回结果中不包含成员 B 的任何私人工作时段或个人剩余估时。
  - Given 项目中某共享任务的截止日期被修改，When 成员 B 打开日程或项目页，Then 系统提示其核查已有私人排期，但不会自动移动成员 B 的私人工作时段。

## 二、非功能性用户故事（NFR-01 至 NFR-02）

### NFR-01：常用视图与资料查找的响应性能
- **用户故事**：作为学生用户，我希望在学期中后期课程、任务和资料积累较多时，打开日/周日程、保存任务和搜索资料依然流畅不卡顿，以便日常查课和记事不拖慢学习节奏。
- **来源**：调研报告第 5.2 节；IV-01、IV-03
- **验收标准**：
  - Given 测试账号包含 20 个工作区、1,000 条任务、2,000 条时段与事件、200 条资料，When 对“打开日视图”“打开周视图”“按名称搜索资料”3 条路径各自独立采集 30 次操作样本并分别计算端到端响应时间 p95（不混测、不遗漏任一路径），Then 3 条路径的 p95 均 ≤ 2 秒。
  - Given 网络正常且服务端可达，When 对“在线保存任务”和“在线保存事件”2 条路径各自独立采集 30 次操作样本并分别计算保存耗时 p95（不混测、不遗漏任一路径），Then 2 条路径的 p95 均 ≤ 3 秒；单次保存请求等待超过 300 毫秒时界面显示“处理中”状态并防止重复提交，保存失败时不清空表单输入。

### NFR-02：共享权限校验与私人数据安全隔离
- **用户故事**：作为项目所有者和项目成员，我希望系统在服务端严格校验每次数据与文件访问权限，并确保账号口令和私人排期不被越权读取或泄露到日志中，以便放心在项目里存放课程资料与个人计划。
- **来源**：调研报告第 5.2 节；IV-04
- **验收标准**：
  - Given 用户未加入项目或已被移出项目，When 直接向服务端请求该项目的任务、事件、资料元数据或附件下载接口，Then 服务端全部返回权限拒绝，不返回任何业务内容。
  - Given 系统完成注册登录与多用户协作操作，When 核查数据库存储与服务端运行日志，Then 数据库中不存在明文密码，日志中不出现口令、会话令牌或用户私人排期明细。
