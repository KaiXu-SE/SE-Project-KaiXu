# KaiXu 软件需求规格说明书

本稿用于第 3 课需求走查，记录 Windows 本地学习规划、账号与小组协作、外部接入三个增量的需求和验收口径。项目范围依据[项目章程](../governance/project-charter.md)，业务目标和指标依据[需求调研报告](research-report.md)。需求与[用户故事](user-stories.md)、[用例图和关键场景](../models/use-cases.md)及[追溯矩阵 v0](traceability-matrix.md)共同提交评审。

## 系统范围与参与者

KaiXu 以课程和项目为工作区，集中管理学习任务、固定事件和资料。独立个人任务与固定事件可以没有工作区。任务截止日期和个人工作时段分别记录。教务管理和群聊沟通由原平台处理。对外部平台的集成限授权只读。外部导入候选、AI 提取结果和排程草案均经用户明确确认后写入正式数据。

| 参与者 | 业务职责 |
| --- | --- |
| 学生用户 | 管理本人工作区、任务、日程、资料与私人时段，核对外部候选。 |
| 项目成员 | 维护有权访问的共享任务、共同事件与项目资料，为本人安排私人时段。 |
| 项目所有者 | 拥有项目成员的权限，另负责首次共享确认、邀请与移除成员、交接所有权和归档恢复。 |
| Canvas | 在授权范围内提供作业数据、记录标识和原作业链接。 |
| AI 服务（扩展） | 根据用户选定的课程群消息或导入的聊天记录返回结构化候选字段。 |

表中前三项为人类主参与者，Canvas 和 AI 服务为次参与者。课表文件是由学生提供的输入。

## 核心对象与状态

[可编辑分析图](../models/use-cases.drawio)中的系统上下文展示客户端、KaiXu 服务与外部来源的交互，核心对象关系页用于核对以下归属及可见范围。

| 对象或术语 | 定义与约束 |
| --- | --- |
| 课程、项目工作区 | 用来组织任务、固定事件和资料。项目可独立存在，或关联一门课程。共享项目有一位所有者和成员关系，课程权限独立判断。 |
| 任务、截止日期 | 任务描述要完成的事项，状态为待办、进行中或已完成。截止日期可以省略，也可只精确到日期。来源平台的提交状态与 KaiXu 任务状态分别记录。 |
| 固定事件、个人工作时段 | 固定事件表示已有的上课、会议等承诺。工作时段表示本人计划执行任务的起止时间。一项任务可以分多段，工作时段和任务截止日期彼此独立。 |
| 任务总估时、个人剩余估时 | 两者都以分钟记录。总估时随任务和编辑权限读取，个人剩余估时仅本人可见。更新一项不会重新计算另一项。 |
| 资料、资料引用、附件版本 | 资料归属工作区，可被同工作区的多条任务引用。解除引用保留资料。附件版本记录上传人、时间和版本号，恢复旧版本时新增一个版本。 |
| 来源记录、待确认候选 | 来源记录保留出处和标识。拉取时区分新候选、无变化的旧记录和待核对变更。候选可待确认、已核对或被忽略。正式任务或事件保存经确认的字段及来源关系。 |
| 保存状态、版本冲突 | 已保存的桌面离线修改可处于待同步，服务端确认后才为已同步。基于旧版本提交时保留待处理输入并展示最新版本。 |
| 排程草案、专注记录 | 草案在确认前只表示建议。专注记录归本人，记录有效时长与达标情况，任务完成仍由用户决定。 |

## 业务规则

| 规则 | 要求 | 对应需求 |
| --- | --- | --- |
| BR01 | 任务和固定事件至多直接归属一个工作区，也可独立。课程与项目之间建立关系时保持各自记录。 | [FR-W02](#fr-w02)、[FR-W05](#fr-w05) |
| BR02 | 截止日与执行时段分开。重叠使用半开区间 [开始，结束)，首尾相接时可按计划保存。 | [FR-S03](#fr-s03)、[FR-S05](#fr-s05) |
| BR03 | 已完成任务和归档任务退出待排池。标记完成时只处理操作者选定的本人未来时段，历史时段保留。编辑或取消个人时段只影响本人选中的时段。 | [FR-S07](#fr-s07)、[FR-W06](#fr-w06) |
| BR04 | 按账号与来源标识识别已确认项。用户确认前，候选仅供检查。 | [FR-I03](#fr-i03)、[FR-I04](#fr-i04) |
| BR05 | 接受来源变化时只更新经确认的字段，保留本地负责人、私人时段和资料引用。来源撤回以提示处理。 | [FR-I05](#fr-i05)、[FR-I06](#fr-i06) |
| BR06 | 首次共享前由所有者确认拟公开范围，成员接受邀请后才获准查看。个人时段、剩余估时和专注记录仅本人可见。 | [FR-C03](#fr-c03)、[NFR-S03](#nfr-s03) |
| BR07 | 每个项目仅一位所有者，接任成员接受前由原所有者负责。 | [FR-C10](#fr-c10) |
| BR08 | 邀请由服务端检查有效期、撤销状态与接受结果。同一邀请至多建立一条成员关系。退出或移除后共享访问即刻收回，原邀请不能恢复资格。 | [FR-C01](#fr-c01)、[FR-C09](#fr-c09) |
| BR09 | 共享写入同时校验当前权限与数据版本，同一业务操作重试只有一次效果。 | [FR-C08](#fr-c08)、[NFR-R03](#nfr-r03) |
| BR10 | 任务只能关联同一工作区有权访问的资料。删除资料仅解除引用，保留任务。 | [FR-R02](#fr-r02)、[FR-R03](#fr-r03) |
| BR11 | 归档内容供有权用户只读回查。恢复时复用原关系，按下表处理个人时段及关联项目。 | [FR-W06](#fr-w06)、[FR-S04](#fr-s04) |
| BR12 | 撤权后保留的个人时段只有起止与本人备注，清除可追溯到受限项目的共享详情、来源和资料。 | [FR-C09](#fr-c09)、[FR-C11](#fr-c11) |
| BR13 | 两端统一按 `Asia/Shanghai` 解释和显示日程。日期型截止保留日期精度，当日结束后未完成才算逾期。有明确偏移量的来源时间按统一时区转换，来源时区有歧义时先核对。 | [FR-T04](#fr-t04)、[FR-I03](#fr-i03)、[NFR-M02](#nfr-m02) |
| BR14 | 已支持的功能在两端使用相同状态、时间校验、权限与冲突规则。两端操作入口按各自增量提供。 | [FR-X02](#fr-x02)、[NFR-M02](#nfr-m02) |
| BR15 | 删除任务后从活动视图移除原任务并停止新增关联时段。已有本人时段保留起止和本人备注并解除任务关联，共享标题、来源及资料随之清理。每个时段所有者可独立处理后续时段，历史保留，重试无额外影响。 | [FR-T02](#fr-t02)、[FR-C11](#fr-c11)、[NFR-R03](#nfr-r03) |

| 归档后的操作 | 规则 |
| --- | --- |
| 编辑工作区内的任务、事件或资料 | 恢复工作区前保持只读。 |
| 给归档任务新增关联时段 | 归档任务退出待排池，恢复后可按当前权限再次安排。 |
| 编辑或取消已有个人时段 | 仅本人可处理这些时段，工作区内容保持只读。 |
| 查看仍存在的未来事件和时段 | 时间视图中保留记录，标注原工作区为归档状态。 |
| 归档有项目关联的课程 | 各关联项目继续保留各自的生命周期与权限。 |
| 恢复工作区 | 恢复对原内容的正常操作，已取消的时段不重建。 |

## 验收环境与记录

以可运行的 Windows 发布包和实际 Android 客户端为验收对象。用访客和至少两个测试账号核对个人使用、切换账号、小组共享与撤权。联调记录注明构建、操作系统与设备、服务端环境、网络条件、样本量、实际结果和失败原因。真实 Canvas 只读接入用获授权课程验收，手动录入有单独的用例。

性能用单账号 20 个工作区、1,000 条任务、2,000 条时段与事件、200 条资料。每条被测路径独立执行一轮 30 次操作，计时从用户动作到结果可用或保存成功反馈。冷、热启动注明口径，外部响应等待单独记录。保留全部操作结果，失败和重试单列。一轮取得 30 个有效样本时，取升序第 29 个为 p95；不足 30 个时，记录本轮证据不足，重测另起一轮。

- 关联需求 [FR-W01](#fr-w01)、[FR-W02](#fr-w02)、[FR-W06](#fr-w06)、[NFR-M03](#nfr-m03)

学生可以创建、编辑、归档和恢复课程或个人项目。项目可关联一个已有课程，也可保持独立。

- Given Windows 访客打开工作区目录，When 选择课程或项目并输入有效名称后保存，Then 目录显示对应工作区，且可以选择课程作为项目的关联。
- Given 名称为空或只含空白，When 保存，Then 界面提示名称必填，保留已输入的字段且工作区数量保持原值。
- Given 用户归档已结课工作区，When 从历史列表查看并恢复，Then 任务、日程和资料均可回查，工作区在恢复后重新出现在默认目录。关联项目的归档状态保持原值，已取消的时段不重建。

### UC-02 创建和维护任务

- 用户故事 `US-02` · M1 · 学生用户
- 关联需求 [FR-W04](#fr-w04)、[FR-W05](#fr-w05)、[FR-T01](#fr-t01)、[FR-T02](#fr-t02)、[FR-T03](#fr-t03)、[FR-T04](#fr-t04)、[FR-C11](#fr-c11)、[NFR-U02](#nfr-u02)、[NFR-U05](#nfr-u05)、[NFR-M01](#nfr-m01)

学生可手动新建或粘贴通知创建任务，查看、编辑及更新任务状态。标题必填，描述、截止日期、优先级、估时和工作区可选。可筛选并查找任务，状态使用待办、进行中与已完成。粘贴录入保存来源类型与原文，有来源链接时一并保存。

- Given Windows 访客录入任务，When 仅填写有效标题并保存，Then 成功创建独立任务且无截止日期时保持未逾期。
- Given 已粘贴一段课程通知，When 用户核对字段、选择工作区并确认保存，Then 正式任务保留原文与来源类型，工作区和全局任务列表指向同一条记录。
- Given 标题为空或用户取消粘贴录入，When 提交无效表单或退出录入，Then 正式任务数量保持原值。无效表单保留当前输入并提示补全。
- Given 一项有截止日期的任务还未安排时段，When 用户从工作区按状态及截止日期筛选并打开该任务，Then 详情标识归属、来源、状态及未排期；无截止日期时不会标成逾期。
- Given 一项任务有本人工作时段，When 确认删除任务，Then 活动任务列表移除任务，已有时段按 BR15 变为无任务关联的个人记录。

### UC-03 核对群消息提取候选

- 用户故事 `US-03` · M3 扩展 · 学生用户、AI 服务
- 关联需求 [FR-I01](#fr-i01)、[FR-I02](#fr-i02)、[FR-I03](#fr-i03)、[FR-I04](#fr-i04)、[FR-I07](#fr-i07)、[NFR-S04](#nfr-s04)、[NFR-A01](#nfr-a01)、[NFR-A02](#nfr-a02)、[NFR-A04](#nfr-a04)、[NFR-A05](#nfr-a05)

学生选择授权范围内的课程群消息或导入聊天记录，通过本人配置的 AI 服务提取建议。候选项保留原文引用、类型和建议字段，日期有歧义时交由学生核对。

- Given 一条通知包含两项作业及模糊日期，When 学生在授权范围内提取并校验结果，Then 分别显示两条带原文的候选，模糊字段标记待核对，重复项提示由学生确认。输入仅限用户核对过的已选文本。
- Given 候选项待核对，When 学生修改并确认其中一条，Then 仅该候选生成正式任务或固定事件。取消、忽略或 AI 服务不可用时，正式数据保持原值，仍可手动录入。
- Given 提取尚在等待或原文包含要求系统改动权限的指令，When 取消请求或收到输出，Then 显示的内容只作为可核对字段，撤销后到达的结果不进入候选或正式数据。
- Given 用户只选中通知正文且原页面还含未选聊天记录，When 用户确认发送范围并发起提取，Then 发送内容只含确认文本，服务密钥只用于鉴权，未选内容和凭据未进入提取正文。

### UC-04 拉取并确认 Canvas 作业

- 用户故事 `US-04` · M3 · 学生用户、Canvas
- 关联需求 [FR-I01](#fr-i01)、[FR-I02](#fr-i02)、[FR-I03](#fr-i03)、[FR-I04](#fr-i04)、[FR-I05](#fr-i05)、[FR-I06](#fr-i06)、[NFR-U05](#nfr-u05)、[NFR-S04](#nfr-s04)、[NFR-P05](#nfr-p05)、[NFR-R02](#nfr-r02)、[NFR-M01](#nfr-m01)

学生授权后只读拉取真实课程作业，预览标题、截止日期（如有）和原作业链接。按授权来源的稳定记录标识去重，来源时间变化由学生核对后应用。

- Given 本地无对应作业且 Canvas 授权有效，When 学生拉取并在预览中确认一条作业，Then 预览期间正式任务数为零，确认后生成一条带来源的任务。
- Given 同一来源作业已确认，When 重复拉取或重复提交确认，Then 只保留一条关联任务。若来源截止日期变化，则展示上次确认值、当前本地值、新源值等待确认，保留本地负责人、个人时段及资料关联。
- Given 授权已失效，When 再次拉取，Then 提示原因与重新授权入口，已导入任务仍可使用，学生可继续手动录入。
- Given 已确认作业后来被原平台撤回或标记已提交，When 再次成功拉取，Then 查看上次成功拉取时间和来源变化提示，已导入任务及其本地状态留存。
- Given 同一账号的两个客户端看到同一版本的候选，When 两端提交相同内容且一端因响应丢失重试，Then 两端取得同一条关联正式任务，正式任务数为一。
- Given 两端看到同一候选且第一端已经确认，When 第二端提交不同截止日期或工作区，Then 现有任务保留已保存值，第二端保留输入供比较并再次确认。

### UC-05 管理固定事件和查看日程

- 用户故事 `US-05` · M1 · 学生用户
- 关联需求 [FR-W05](#fr-w05)、[FR-S01](#fr-s01)、[FR-S02](#fr-s02)

学生可维护上课、考试等固定事件。日视图、周视图与工作区视图展示来自同一数据源的固定事件和个人工作时段。

- Given 正在新建课程固定事件，When 保存有效标题且结束晚于开始，Then 该事件同时显示在对应日期的日／周视图及所属工作区。按工作区筛选时仍引用原事件。
- Given 结束时间早于或等于开始，When 点击保存，Then 提示修正时间并保留输入，正式日程保持原值。

### UC-06 将任务安排到多个私人时段

- 用户故事 `US-06` · M1 · 学生用户
- 关联需求 [FR-S03](#fr-s03)、[FR-S04](#fr-s04)

同一任务可安排多个独立的执行时段。编辑或删除某时段时只处理该时段，任务截止日期单独保存。

- Given 一个已有截止日期的未完成任务，When 分别安排周二和周四的工作时段，Then 任务详情显示原截止日期和两个时段，日程按实际时间展示。
- Given 任务有两个工作时段，When 删除其中一个，Then 任务与另一个时段仍可查询。
- Given 任务只填标题，When 用户手动排期并先输入无效起止再改正，Then 无效输入留在表单供修正，合法起止可保存。

### UC-07 发现排期冲突与超期

- 用户故事 `US-07` · M1 · 学生用户
- 关联需求 [FR-S05](#fr-s05)、[FR-S06](#fr-s06)、[NFR-M02](#nfr-m02)

排期与本人固定事件或已有时段重叠，或工作时段超出原截止日期时，系统列出原因，由学生修改或明确确认。相邻时段按半开区间判断。

- Given 本人已有 14:00–16:00 的固定课，When 安排 15:00–17:00 的时段，Then 系统列出重叠对象并提供返回修改或确认保留的选项。
- Given 已有 14:00–15:00 的安排且任务周五截止，When 保存首尾相接的时段或尝试排到周六，Then 15:00 开始的相邻时段无需重叠确认，周六的安排触发超期提示并保留原截止日期。
- Given 截止字段只有日期，两端设备时区不同，When 校验该日末尾及次日开始的安排，Then 两端按 `Asia/Shanghai` 的同一日期边界判断，不向原日期型字段写入额外时间。

### UC-08 提交任务完成与剩余估时

- 用户故事 `US-08` · M1 个人任务、M2 共享任务 · 学生用户、项目成员
- 关联需求 [FR-T02](#fr-t02)、[FR-S07](#fr-s07)、[FR-S08](#fr-s08)

有本人未来时段的任务在完成前展示时段清单，请操作者决定保留或取消。状态与选定的本人未来时段处置一并保存，历史时段及其他成员的私人安排保留。未完成时可更新本人剩余估时和后续时段。

- Given 还有一条历史时段和两条本人未来时段，When 标记为完成并确认保留或取消未来时段，Then 任务变为已完成，历史保留，未来时段按所选结果保留或从个人日程移除。
- Given 已打开完成确认，When 学生取消或保存失败，Then 状态与时段均保持原值；失败时保留选择供重试。
- Given 共享任务尚未完成，When 成员更新本人剩余估时和后续计划，Then 仅本人的估时与选定时段更新，历史及其他成员的数据保持原值。
- Given 已完成任务原先取消了未来时段，When 将状态恢复为未完成，Then 任务可以重新进入排程，历史时段持续可见，已取消的时段不重建。

工作区管理链接和简短文本。任务在 M3 可关联有权访问的同工作区资料，成员从任务详情打开资料。

- Given Windows 访客在课程工作区保存一条链接和一则笔记，When 正常退出后重新启动，Then 两项资料及其工作区归属仍可读取。
- Given 任务与可访问资料属于同一工作区，When 用户关联资料并打开任务详情，Then 最多两次点击即可打开资料；解除关联后资料仍在工作区。
- Given 资料已被任务引用，When 删除资料并确认影响，Then 确认前展示受影响任务数，确认后系统移除资料及关联并保留原任务。

### UC-10 邀请成员和撤回访问

- 用户故事 `US-10` · M2 · 项目所有者、项目成员
- 关联需求 [FR-C01](#fr-c01)、[FR-C02](#fr-c02)、[FR-C03](#fr-c03)、[FR-C09](#fr-c09)

所有者首次共享前确认公开的任务、事件和资料。受邀者确认加入后建立成员关系；退出或被移除时服务端随即撤回访问权限。

- Given 所有者第一次共享个人项目，When 发起共享，Then 界面列出将公开的项目内容，只在所有者确认后生效，个人工作时段继续仅本人可见。
- Given 一个有效的邀请，When 受邀者确认并再次使用同一邀请，Then 只产生一条成员关系；过期、被撤销或已由另一账号消费的邀请不能创建新成员关系。
- Given 成员已经退出或被移除，When 用原邀请再次加入，或用原会话读写项目，Then 服务端拒绝，项目历史仍保留。重新加入需新的有效邀请。

### UC-11 维护共享任务与共同事件

- 用户故事 `US-11` · M2 共享任务、固定事件及资料权限 · 项目成员
- 关联需求 [FR-S01](#fr-s01)、[FR-S05](#fr-s05)、[FR-C04](#fr-c04)、[FR-C05](#fr-c05)、[FR-C07](#fr-c07)、[FR-C08](#fr-c08)、[NFR-R03](#nfr-r03)

已获授权的成员可新增、编辑或删除共享任务，维护负责人、状态、阻碍和共同事件，并处理权限范围内的共享资料。记录显示最近修改人与时间，保存时校验版本。

- Given A、B 同属项目且具有写权限，When A 更新任务负责人、状态或共同事件，Then B 刷新后看到最新内容及可追溯的修改信息。
- Given A、B 基于同一旧版本编辑，When A 先保存且 B 后提交，Then 系统保留 B 的输入并展示差异供比较，当前版本仍为 A 的保存结果。
- Given 一名成员维护共同事件，When 更新起止时间或确认删除，Then 只检查操作者本人的冲突和其当前权限，其他成员刷新时读到同一事件的最新状态。

### UC-12 保留并隔离私人安排

- 用户故事 `US-12` · M2 · 项目成员
- 关联需求 [FR-T02](#fr-t02)、[FR-S03](#fr-s03)、[FR-S04](#fr-s04)、[FR-S05](#fr-s05)、[FR-S08](#fr-s08)、[FR-C06](#fr-c06)、[FR-C07](#fr-c07)、[FR-C09](#fr-c09)、[FR-C11](#fr-c11)、[NFR-S03](#nfr-s03)、[NFR-S05](#nfr-s05)

成员可将共享任务安排到本人日程。个人工作时段、剩余估时和专注记录仅本人可见。共享任务删除或成员退出、被移除后，相关个人时段保留时间与个人备注，清除共享标题、资料摘录及其与原任务和阶段的关联。

- Given B 已为共享任务排期，When 项目所有者读取共享任务或推进进度，Then 共享结果中仅包含可共享信息，B 的时段和剩余估时仍仅 B 可见。
- Given 共享任务截止日变化，When B 查看个人日程，Then 系统提示检查安排，并保持原时段位置。
- Given 共享任务被删除或 B 失去成员资格，When B 重新读取或桌面重连，Then 保留本人时段与备注，清除相关的共享内容与关联。B 失去成员资格时，服务端立即拒绝其项目访问，桌面重新获知撤权后清理对应的缓存、草稿和待同步操作。

### UC-13 管理登录和桌面离线同步

- 用户故事 `US-13` · M2 · 学生用户
- 关联需求 [FR-C08](#fr-c08)、[FR-X01](#fr-x01)、[FR-X02](#fr-x02)、[FR-X03](#fr-x03)、[FR-X04](#fr-x04)、[FR-X05](#fr-x05)、[FR-X06](#fr-x06)、[NFR-S05](#nfr-s05)、[NFR-P03](#nfr-p03)、[NFR-R03](#nfr-r03)

学生可注册、登录和退出。Windows 的访客与各账号数据分开存放。游客数据仅经明确确认导入。已登录的桌面支持断网编辑和重启恢复待同步修改，重连后校验当前权限与数据版本并自动补传。

- Given 访客已创建本地记录，When 登录并拒绝或明确确认导入，Then 拒绝时记录仍留在访客空间，确认时才导入当前账号；切换账号只读取当前账号的文件、草稿与待同步队列。
- Given 已登录的桌面断网保存后重启，When 以同一账号重新使用并恢复网络，Then 本地修改和同步状态得以恢复，未送达时显示待同步，服务端确认后标已同步。有权且版本匹配的修改只生效一次。仍有权限的版本冲突保留待确认输入。
- Given 桌面恢复联网但暂未取得权限结果，When 轮到共享操作补传，Then 继续标为待同步。确认有权后才进入版本校验，确认撤权时清理该项目中已失去权限的共享缓存、草稿和待同步操作。

### UC-14 处理 Android 在线日常操作

- 用户故事 `US-14` · M2 在线查看、改状态和改期 · 学生用户、项目成员
- 关联需求 [FR-X01](#fr-x01)、[FR-X02](#fr-x02)、[FR-X03](#fr-x03)、[FR-X04](#fr-x04)、[FR-X05](#fr-x05)、[FR-X06](#fr-x06)、[NFR-U04](#nfr-u04)、[NFR-P03](#nfr-p03)、[NFR-M02](#nfr-m02)、[NFR-M03](#nfr-m03)

Android 在登录且联网时提供授权范围内的日程查看、任务状态更新及本人已有时段的简单改期。快速录入保留为产品需求，其增量由组内评审确认，见 [Android 快速录入方案](review-proposals.md#android-快速录入)。

- Given 用户在 Android 已登录且联网，When 查看授权日程、修改任务状态并调整本人已有时段，Then 更新保存后可在同账号 Windows 刷新核对。
- Given Android 遇到断网或会话失效，When 继续使用并在连接与授权恢复后重进，Then 业务视图在失效期间收起，恢复后按当前权限重新读取。
- Given 快速录入已列入某增量且用户已登录联网，When 输入有效标题并确认，Then 生成一条可在同账号查看的任务。

### UC-15 查看并确认规则排程草案

- 用户故事 `US-15` · M3 · 学生用户
- 关联需求 [FR-S09](#fr-s09)、[FR-S10](#fr-s10)

规则排程根据截止日期、本人剩余估时、固定事件、可用时间和任务依赖生成建议。缺少必要信息、可用时间不足或依赖冲突时给出原因，由学生修改或确认。

- Given 用户选中有截止日期和估时的任务，When 生成草案，Then 界面在现有固定事件以外排列建议时段，并列出因容量或依赖冲突无法安排的任务。
- Given 草案已生成，When 学生取消或明确确认，Then 取消时正式日程保持原值，确认时只保存所确认的时段。
- Given 已有正式时段或缺少必要估时，When 再次生成草案，Then 正式日程保持原值，系统列出差异、缺少的估时及未排上的事项。

### UC-16 管理附件版本与授权下载

- 用户故事 `US-16` · M3 · 学生用户、项目成员
- 关联需求 [FR-R03](#fr-r03)、[FR-R04](#fr-r04)、[FR-R05](#fr-r05)、[FR-R06](#fr-r06)、[NFR-R04](#nfr-r04)

有权的用户可上传与下载附件并查看历史版本及上传者、时间、版本号。上传成功后再切换当前版本，恢复旧附件时根据旧内容创建新版本。

- Given 工作区附件已有版本 A，When 上传版本 B 中途失败，Then A 仍可通过原入口读取且当前版本保持为 A。
- Given A、B 均已保存，When 有权用户恢复 A，Then 新版本内容为 A 且原有历史仍可查；失去访问权的成员请求附件时服务端拒绝返回内容。

### UC-17 记录 Android 在线番茄钟

- 用户故事 `US-17` · M3 · 学生用户
- 关联需求 [FR-X02](#fr-x02)、[FR-X07](#fr-x07)、[NFR-U04](#nfr-u04)、[NFR-S03](#nfr-s03)

用户可在登录联网的 Android 上对本人已有工作时段开始番茄钟。断网暂停，重连时核对原会话与累计有效时长。达到目标的 70% 即记为达标，任务完成由本人决定。

- Given 目标时长为 20 分钟，When 结束本次计时，有效时长分别为 13 分钟与 14 分钟，Then 前者未达标、后者达标，任务状态保持原值，学生可另行更新。
- Given 番茄钟计时中断网，When 重连并恢复同一会话，Then 离线期间暂停累计，已计时长保留，专注记录仅本人可读。

### UC-18 交接所有权并管理项目生命周期

- 用户故事 `US-18` · M2 · 项目所有者、项目成员
- 关联需求 [FR-W06](#fr-w06)、[FR-C02](#fr-c02)、[FR-C10](#fr-c10)

所有者可提名有效成员接任，也可归档或恢复共享项目。受提名成员接受前，原所有者继续负责。角色和状态改变后依据当前权限校验管理请求。

- Given B 是项目的有效成员，When 所有者 A 发起交接且 B 接受，Then B 获得所有者权限，A 成为成员。接受前取消或 B 拒绝时 A 仍为所有者，普通成员自行发起交接时被拒绝。
- Given 项目已归档，When 当前所有者恢复项目，Then 默认项目目录重新显示原项目，历史任务、事件和资料均可回查。

### UC-19 预览并导入标准课表

- 用户故事 `US-04` · M3 · 学生用户
- 关联需求 [FR-I08](#fr-i08)、[FR-S11](#fr-s11)、[NFR-R02](#nfr-r02)

学生上传约定格式的学期课表，预览课程匹配与上课时间。用户一次确认的课程工作区和相应上课固定事件一起生效，同一份课表可安全重试。[标准课表候选格式及样例](review-proposals.md#标准学期课表)供评审核对。

- Given 一份符合约定格式且含未建课程的课表，When 解析预览，然后由学生确认，Then 预览阶段正式数据保持原值，确认后可在课程目录和日程中同时查到课程及上课固定事件，包含周期信息时依预览展示的日期落地。
- Given 同一份课表已导入，When 再次解析并确认，Then 对应课程工作区和固定事件数量保持原值。格式不符合约定或取消时，正式数据也保持原值。
- Given 一份课表包含一个待新建课程和两个上课事件，When 确认入库时模拟事件写入失败，Then 本批无课程或事件生效，已有正式数据保持原值。重试成功后只增加一个课程和两个事件。

### UC-24 查看工作区概览

- 用户故事 `US-19` · M1，M2 共享权限 · 学生用户、项目成员
- 关联需求 [FR-W02](#fr-w02)、[FR-W03](#fr-w03)、[FR-W04](#fr-w04)、[FR-T04](#fr-t04)、[FR-S02](#fr-s02)、[FR-R01](#fr-r01)、[NFR-U02](#nfr-u02)

从工作区概览查看未完成任务、近期截止、关联日程与资料入口。所有入口指向当前用户有权打开的原记录。

- Given 一门课程已有未完成任务和固定事件，When 从概览进入最近截止的任务并修改状态，Then 概览和全局任务列表反映同一条记录及状态。
- Given 账号拥有项目权限但无关联课程权限，When 打开项目概览，Then 仅显示不带课程名、简介或链接的私有课程提示，且仍能查看已获准的项目记录。

#### 五名学生独立找任务

1. 在同一 Windows M1 构建的本地模式准备五份相同的预置数据，每份包含两个工作区和至少两个同名任务。例如「软件工程示例」和「数据库示例」各有一条「实验报告」，以软件工程示例下的那条为目标。每位学生从首页独立开始，测试员只给出目标工作区和任务标题。
2. 从读完目标并示意开始计时，观察学生自行打开任务详情。学生表示已找到或结束尝试时停表，核对最终打开任务的标题与所属工作区。下一位开始前恢复首页和原始预置数据。
3. 按参与者代号记录构建版本、实际操作步骤、耗时、误开任务或其他错误、是否接受帮助、最终定位结果及通过情况。误开后自行纠正时仍记录错误和耗时。

**通过条件** 五名学生均从首页独立打开指定工作区下的正确任务详情。需要路线提示、结束时停在错误任务或未找到的参与者计为未通过，整轮以 5/5 通过为准。耗时用于记录和比较。

### UC-25 查看和汇报共享进度

- 用户故事 `US-20` · M2 · 项目成员
- 关联需求 [FR-C04](#fr-c04)、[FR-C07](#fr-c07)

进度页显示项目任务的负责人、状态、截止时间、简短阻碍与最近修改信息。成员通过更新共享任务汇报进展，私人执行安排仅本人查看。

- Given A 和 B 都是当前项目成员，When A 汇报任务状态与阻碍、B 刷新进度页，Then B 可见最新进度及修改信息，任务详情与进度页引用同一记录。
- Given A 和 B 各自安排了本人工作时段，When 读取项目进度和项目接口，Then 各自的时段和剩余估时仅本人可读，共享结果只含项目进度。

## 非功能验收用例

### UC-20 测量常用操作性能

- 用户故事 `NFR-01` · M3 全量验收 · 验收人员
- 关联需求 [NFR-P01](#nfr-p01)、[NFR-P02](#nfr-p02)、[NFR-P04](#nfr-p04)

在单账号含 20 个工作区、1,000 条任务、2,000 条时段与事件、200 条资料的测试数据下，记录构建、设备、网络及每条路径的独立样本。计时从用户操作开始，到界面可用或保存成功提示显示为止。每条路径独立测量和记录每轮 30 次操作，p95 的取样口径见[验收环境与记录](#验收环境与记录)。

- Given 使用上述数据规模和同一构建，When 分别测量日视图、周视图和按名称搜索资料且各取得一轮 30 个有效样本，Then 三条路径的 p95 分别不超过 2 秒。
- Given 网络正常且服务端可达，When 分别测量在线保存任务与在线保存事件且各取得一轮 30 个有效样本，Then 两条路径的 p95 分别不超过 3 秒；单次等待超过 300 毫秒时显示处理中并防止重复提交。
- Given 某条被测路径的一轮 30 次操作中有失败，When 生成本轮验收记录，Then 失败结果与重试次数保留，本轮标记为缺少完整的 p95 判定证据。

### UC-21 验证服务端权限与私密数据隔离

- 用户故事 `NFR-02` · M2，M3 补充附件下载 · 验收人员
- 关联需求 [FR-R03](#fr-r03)、[FR-X06](#fr-x06)、[NFR-S01](#nfr-s01)、[NFR-S02](#nfr-s02)、[NFR-S03](#nfr-s03)、[NFR-S04](#nfr-s04)、[NFR-S05](#nfr-s05)、[NFR-M04](#nfr-m04)、[NFR-A04](#nfr-a04)

共享任务、事件、资料及附件的每次读写均由服务端校验当前成员资格。口令须安全存储，日志排除口令、会话令牌和私人排期明细。

- Given 未加入项目或已被移除的测试账号，When 用该账号读取或修改共享任务、事件、资料，或在附件交付后请求下载，Then 请求被拒绝且响应不含业务内容。
- Given 完成注册登录和多用户协作，When 核对存储、日志及共享接口返回，Then 数据库不含明文口令，日志不含口令、令牌或私人排期明细，共享响应只含获授权的业务数据。

#### 登录与同步的加密验收

1. 在 M2 测试环境准备 Windows 和 Android 验收构建、测试账号及客户端信任的 HTTPS 证书。两端分别登录。用 Windows 保存一项变更并同步，用 Android 读到该变更后更新任务状态，再从 Windows 刷新确认同步结果。
2. 结合客户端网络诊断和测试网关的 TLS 握手记录，核对两端的登录和同步请求使用 HTTPS，并通过证书验证。按端和操作记录构建、测试配置、连接协议、证书验证结果及是否观察到明文业务请求。验收记录仅保留检查结果，省略账号凭据及业务内容。
3. 使用相同构建分别连接证书不受客户端信任、以及仅提供 HTTP 的测试入口，每种配置都建立新连接。在未登录状态尝试登录，在正常配置下已取得测试会话的客户端上再分别尝试同步，核对失败提示及测试入口接收的请求。

**通过条件** 两端的正常登录与同步均使用通过证书验证的 HTTPS 连接且流程成功。证书验证失败或仅有 HTTP 时，登录与同步应中止并提示连接失败，测试入口及网络记录均无明文口令、会话令牌或同步数据。

### UC-22 验证保存重试与版本一致性

- 用户故事 `NFR-03` · M1 保存恢复，M2 重试与版本冲突 · 验收人员
- 关联需求 [FR-X04](#fr-x04)、[NFR-U05](#nfr-u05)、[NFR-R01](#nfr-r01)、[NFR-R02](#nfr-r02)、[NFR-R03](#nfr-r03)、[NFR-R04](#nfr-r04)、[NFR-M02](#nfr-m02)、[NFR-M04](#nfr-m04)

保存失败时保留仍有访问权的输入。已保存或待同步的数据按其状态在桌面重启后恢复。重复请求只产生一次副作用，旧版本提交进入人工处理。

- Given 数据已成功保存，When 退出并重启 Windows 桌面端，Then 保存结果与原关联均可读取。
- Given 已提交保存但响应丢失，When 用同一操作重试三次，Then 只产生一次业务变更；若保存未成功且用户仍有权限，保留原表单和重试入口。
- Given 两个用户基于同一版本同时修改，When 其中一人先保存，Then 后提交方看到版本差异和自己的输入，已保存版本等待其确认后才会变更。

### UC-23 验证快速录入和资料打开步数

- 用户故事 `NFR-04` · M1 桌面快速录入，M3 资料打开 · 验收人员
- 关联需求 [NFR-U01](#nfr-u01)、[NFR-U03](#nfr-u03)、[NFR-U04](#nfr-u04)

按主要点击步骤计数，输入文字不计入操作次数。分别验证桌面快速建独立任务和从任务详情打开资料。

- Given 学生已打开 Windows 首页，When 打开快速录入、填写有效标题并保存独立任务，Then 从首页到看到保存结果不超过 4 次主要操作。
- Given 任务已关联同工作区的可访问资料，When 从任务详情打开该资料，Then 不超过 2 次点击。
- Given Android 已交付相应功能，When 在实际测试机调大系统字体并执行查看、改状态或改期，Then 核心控件仍可找到，文本可读且确认和取消入口可触达。

### UC-26 验证本地库升级和回退

- 用户故事 `NFR-05` · 涉及 Windows 本地库升级的增量 · 验收人员
- 关联需求 [NFR-R06](#nfr-r06)、[NFR-M03](#nfr-m03)

升级前备份正在使用的旧版数据库。用成功和受控失败两条路径核对原有任务、时段、资料及其关系。

- Given 含任务和时段及已交付资料关联的旧版测试数据库，When 生成可读备份并成功迁移，再重启新版，Then 原记录、归属与关联均可查询。
- Given 同一旧库的另一份测试副本，When 模拟迁移中断并恢复升级前备份，再用旧版打开，Then 旧版可正常工作且原记录与关联完整，受影响数据没有停留在混合版本状态。
