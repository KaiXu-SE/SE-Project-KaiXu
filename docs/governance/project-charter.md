# KaiXu（开序）项目章程

## 项目背景与目标

KaiXu 面向高校学生，服务于日常学习、期末复习和课程小组项目。团队访谈了 5 名学生。有人要在 Canvas 和课程群之间核对作业要求，有人记下了截止日期，到期末才发现几门课的任务挤在同一周。做小组作业时，组长想知道谁负责、做到哪一步，成员则希望自己安排时间，也能随时找到要用的资料。

项目以课程和项目为工作区，将任务、日程和资料放在一起。交付后，用以下场景检验项目是否解决了这些问题。

| 业务目标 | 验收时要看到的结果 |
| --- | --- |
| 少漏记、少重复录入 | 学生能核对通知原文、标题和截止时间。确认后生成任务，重复拉取同一份 Canvas 作业只产生一条任务。 |
| 把作业排进一周的空闲时间 | 学生能在同一周安排两门课的任务和一个个人事件，把一项作业分到多个时段。与上课时间重叠或排到截止日期之后时，日历给出提示。 |
| 做任务时能找到资料 | 学生可以把链接、笔记和附件关联到同一工作区的任务，从任务详情最多点击两次即可打开资料，附件更新后仍能恢复旧版。 |
| 小组能看到进度，成员能保留私人安排 | 至少两人能共同维护任务负责人、截止时间、状态和遇到的问题。两人可以给同一任务安排不同的工作时段，各自只看到自己的安排。 |

## 产品范围

- **Windows 桌面端**是主工作台。学生无需登录即可在本机管理课程、项目、任务、固定事件和资料，也能记录不属于任何课程的个人事项。课程项目可以关联到课程。登录后断网仍可编辑，退出再打开时保留修改，恢复联网后自动补传。访客数据经本人确认后才导入账号。
- **Android 端**在登录且联网时使用。学生可以查看日程、快速录入任务、更新任务状态、调整本人已有的工作时段，并为该时段启动番茄钟。断网时暂停计时，重连后核对已记录的时长。是否完成任务由学生决定。
- **外部接入**包括经授权只读拉取真实 Canvas 作业，以及导入标准格式的学期课表。两者都先预览，由学生核对后保存。确认课表后，系统同时建立课程工作区和对应的上课固定事件。
- **课程群消息是扩展项。** 学生可选取已获授权的微信、QQ 课程群消息或导入聊天记录，用自己的 AI 服务密钥提取建议。学生可以修改、忽略或确认候选项，只有确认的内容才写入正式任务或日程。手动录入始终可用。

本期不替代教务系统，不提供多人在线文档编辑或 Git 代码托管，也不向微信、QQ 或 Canvas 回发消息。

## 用户角色与权限

| 角色 | 可以做什么 |
| --- | --- |
| 学生用户 | 管理自己的课程、个人项目、独立事项和资料，安排和调整自己的学习时间。 |
| 项目成员 | 查看和维护本项目的共享任务、共同事件和资料，更新负责人、状态和遇到的问题，并将共享任务排入自己的日程。 |
| 项目所有者 | 拥有成员的权限。首次共享前确认公开哪些内容，邀请或移除成员、交接所有权，以及归档或恢复项目。 |

服务端每次读写共享任务、事件和资料（含下载附件）都检查当前成员资格。个人工作时段、个人剩余估时和专注记录仅本人可见。共享任务被删除，或成员退出、被移除后，受影响的个人时段仍保留起止时间和个人备注。系统会清除其中的共享任务标题和资料摘录，并解除与原任务、原阶段的关联。

## 交付计划与验收

四人团队按三个增量交付。个人排期是小组协作的基础，先用桌面版验证学生能否独立安排一周，再用两个账号检验同步和共享权限。外部接入随第三版交付，Canvas 授权和首次真实拉取提前到 11 月 27 日前验证，给联调留出时间。

各增量内按短迭代推进，每轮安排计划、构造、测试和评审。具体安排见[过程模型选型](process-model.md)，组内讨论记录见[选型 Issue #9](https://github.com/KaiXu-SE/SE-Project-KaiXu/issues/9)。

| 增量与计划发布日期 | 交付内容 | 验收重点 |
| --- | --- | --- |
| M1 · v0.1.0 · 2026-12-11 | Windows 本地工作区、任务、固定事件、个人分段排期、日／周视图、链接和文本资料。同步完成需求与设计文档。 | 未登录时创建课程和项目，手动创建一项独立任务和一项课程任务。将一项作业分到两天，检查重叠和超期提示。归档后能恢复工作区，重启后核对任务字段、状态和时段。归档需求规格说明书（SRS）v1.0、分析模型和设计评审记录。 |
| M2 · v0.2.0 · 2026-12-16 | 账号与服务端、桌面离线同步、成员邀请与所有权交接、共享任务和事件，以及 Android 在线查看、改状态和改期。 | 用访客和两个账号验证数据隔离。桌面断网修改并重启，重连后重复提交只生效一次。两人同时编辑时能核对差异。成员被移除后无法再打开项目，仍能查看自己原有的时段。 |
| M3 · v0.3.0 · 2026-12-24 | Canvas 作业拉取、标准课表导入、任务与资料关联、附件版本、规则排程、Android 番茄钟、选定的群消息扩展及全量验收。 | 重复拉取作业或导入课表均无重复记录，旧附件能恢复。排程显示时间不足或任务依赖冲突，确认后才写入。番茄钟有效计时达到目标的 70% 时记为达标。完成全量回归、性能测试和部署验证，归档结果后发布。 |

课程交付至少包含 **3 个可运行增量、20 个用例（其中至少 2 个为非功能用例）、15 个分析类**，并验证上述三类角色的权限和实际外部接入。每版保留运行说明、测试结果和验收记录。最终验收时，打开日视图、打开周视图、按名称搜索资料各测 30 次，每项响应时间的第 95 百分位（p95）均不超过 2 秒。在线保存任务、在线保存事件也各测 30 次，每项 p95 不超过 3 秒。测试数据规模见[需求调研报告](../requirements/research-report.md)。

需求由需求分析师组织核对，架构决定由设计负责人组织评审，合并由至少一名非作者组员批准。这三处都由成员署名记录结论。章程的范围和下表风险由小组讨论，在 Issue #8 或关联 PR 中记录确认结果。PR 写明实际验证情况和 AI 使用情况，通过 `docs-check` 后合入 `main`。

基线定稿后，调整范围先提 `type:change` Issue，写明原因及对用例、设计、测试和里程碑的影响。小组确认后，通过关联 PR 一并更新受影响的文档、实现和验收记录。

## 主要风险与应对

| 风险 | 提前怎么验证 | 出现问题时怎么办 |
| --- | --- | --- |
| Canvas 授权失效，群消息中的多项作业被漏记或重复建立 | 用真实课程试拉取，撤销授权后再试一次。用一条含两项作业的群消息重复提取，检查能否分别确认且各建一条。 | 授权失效时保留已导入任务，提示重新授权，期间可手动录入。群消息保留原文，按作业分别去重，有歧义时由学生核对。 |
| 桌面离线修改丢失，或两人同时修改时互相覆盖 | 断网改任务后重启，让另一账号改同一任务，再重连并重复提交。 | 本地保留待同步修改，同一操作重试只生效一次。有冲突时显示两份内容，由用户确认采用哪一份。 |
| 成员被移除后仍能读项目或上传离线修改 | 移除成员后，用其原会话打开任务和附件，再让离线桌面重连补传。 | 服务端立即拒绝失去权限的请求。桌面重连先查权限，清除受限内容，保留已解除关联的本人时段。 |
| 本地数据库升级丢失旧数据 | 用含任务、时段和资料关联的旧版数据库试升级，核对记录和关联，再重启检查。 | 升级前备份。迁移失败时恢复备份，用旧版继续工作。 |
| 四人并行做双端和后端，联调时间不足 | 每个增量先选一条学生会用到的流程做联调，在看板标出谁负责、哪项工作在等前一步。 | 优先保证本轮验收功能。需要缩减或推迟扩展时，由项目经理发起范围变更并更新排期。 |

立项与交付依据见[选题 Issue #4](https://github.com/KaiXu-SE/SE-Project-KaiXu/issues/4)、[章程 Issue #8](https://github.com/KaiXu-SE/SE-Project-KaiXu/issues/8) 和[仓库里程碑](https://github.com/KaiXu-SE/SE-Project-KaiXu/milestones)。
